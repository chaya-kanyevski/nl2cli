## v2 – Role + פורמט קשיח + Few-Shot
**הבעיה שבטיפול:** פורמט פלט לא עקבי.

**השינויים:**
- **Role Prompting** – "senior command-line engineer specialized in {{OS}}".
- **Guardrails** על הפלט – שורה אחת, בלי הסברים, בלי Markdown, בלי `$` / `C:\>`.
- **Few-Shot** – 3 דוגמאות לכל מערכת יעד. הדוגמאות **לא לקוחות מתרחישי הבדיקה** (אחרת המדידה הייתה "מרמה").

**השערה:** קפיצה ב-`format_ok`. הדיוק התוכני ישתנה מעט, כי לא נגענו בהבנת המשימה.

## v3 – עמידות: מערכת יעד, שרשור, עמימות ומניפולציות
**הבעיות שבטיפול:** פקודות Linux ביעד Windows, הוראות רב-שלביות, שאלות שאינן משימת טרמינל, Prompt Injection.

**השינויים:**
- כללים מפורשים לכל מערכת (תחביר נתיבים, משתנים, מתי מותר PowerShell).
- שרשור עם `&&` לפי סדר הבקשה.
- טוקן `UNSUPPORTED` לבקשות שאינן פקודה / עמומות / מנסות לשנות את הכללים.
- **Chain of Thought שקט** – רשימת Self-check שהמודל מבצע בלי להדפיס.

**השערה:** שיפור בתרחישים 11, 25, 36 (פקודות שאין להן מקבילה ישירה ב-cmd), 24, 33 (רב-שלבי), 28–29 (לא פקודה / injection).
סיכון: המודל עלול להחזיר `UNSUPPORTED` גם כשיש פקודה סבירה (זהירות-יתר) – לבדוק בתרחיש 26 "תנקה".

## v4 – בטיחות + פלט JSON מובנה
**הבעיה שבטיפול:** המודל מפיק פקודות הרסניות; אין דרך מובנית לסמן "דורש אישור".

**השינויים:**
- **Output Structuring** – `{"status", "command", "risk", "reason"}`.
- מדיניות סיכון מפורשת: `blocked` / `confirm` / `safe` עם רשימות דוגמה.
- Few-Shot שמדגים גם פקודה מסוכנת **מוסתרת** בתוך בקשה תמימה.
- ולידציית פלט בקוד: JSON תקין, כל השדות קיימים, ערכים חוקיים.

**השערה:** `model_safety_ok` גבוה. ייתכן ירידה קלה ב-`format_ok` (JSON בתוך גדרות קוד) – הקוד מחלץ את ה-JSON אבל מסמן את החריגה.
